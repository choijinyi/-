# 블렌더 프리비즈 → Seedance 영상 제작

## 이 워크플로가 푸는 문제

텍스트 프롬프트만으로 AI 영상을 뽑으면 카메라 무브와 인물 위치가 매번 달라져서, 원하는 컷이 나올 때까지 크레딧을 태우게 된다. 이 워크플로는 순서를 뒤집는다. 무료인 블렌더에서 카메라·동선·타이밍을 먼저 확정하고("Block it. Lock it. Generate it."), 그 프리비즈 영상을 Seedance의 비디오 레퍼런스로 넣어 움직임은 프리비즈에서, 룩은 별도 이미지 레퍼런스에서 가져오게 한다. 비싼 생성 단계에서 시행착오를 하지 않는 것이 비용 절감의 실체이다.

따라서 이 스킬의 판단 기준은 하나다. **크레딧이 드는 단계에 들어가기 전에, 크레딧이 안 드는 단계에서 불확실성을 최대한 없앴는가.**

## 두 커넥터의 역할

| | Higgsfield Bridge | Higgsfield MCP |
|---|---|---|
| 하는 일 | 블렌더 씬 조작·렌더링 | 업로드, 이미지·영상 생성 |
| 주소 | `https://bridge.higgsfield.ai/mcp` | `https://mcp.higgsfield.ai/mcp` |
| 필요 조건 | 블렌더 실행 중 + 플러그인 로그인 | 없음(계정 크레딧 사용) |
| 쓰는 단계 | 2~3단계 | 4~7단계 |

도구 이름은 환경마다 다르게 붙으므로(예: `mcp__...Higgsfield...__generate_video`) 이름을 외워 부르지 말고 현재 세션의 도구 목록에서 확인한다. 둘 중 하나라도 없으면 `references/setup.md`를 읽고 사용자에게 연결 절차를 안내한 뒤, 연결 없이 할 수 있는 일(샷 리스트 설계, 프롬프트 초안)부터 진행한다. Bridge가 없어도 사용자가 직접 렌더한 프리비즈 mp4를 주면 4단계부터 이어갈 수 있다.

## 워크플로

### 1. 연결 확인과 샷 설계

Bridge로 현재 씬의 오브젝트 목록을 읽고, MCP로 크레딧 잔액을 확인한다. 둘 다 응답하면 연결은 정상이다.

씬을 만들기 전에 사용자의 의도를 샷 리스트로 정리해 합의한다. 컷 번호, 시작·끝 초, 카메라(화각·위치·무브), 인물별 동선, 핵심 소품을 적는다. 이 표가 뒤의 블렌더 마커, 초 단위 분석, 프롬프트의 공통 뼈대가 되므로 여기서 어긋나면 뒤가 전부 어긋난다.

길이는 24fps 기준으로 프레임을 계산한다(초 × 24. 8초=192, 11초=264, 22초=528, 30초=720). Seedance 한 번 생성의 최대 길이는 모델 버전에 따라 다르니 MCP의 모델 조회로 확인하고, 그보다 긴 영상은 그 단위로 잘라 따로 생성한 뒤 편집에서 잇는다. 한 컷은 1.5초 이상으로 잡는다. 0.8초 미만의 컷은 생성 결과에서 뭉개진다.

### 2. 블렌더에서 프리비즈 씬 구성 (Bridge)

프리비즈는 룩이 아니라 타이밍과 위치를 전달하는 시안이다. 회색 박스와 캡슐이면 충분하고, 공들인 모델링은 오히려 Seedance가 그 스타일을 따라 그릴 위험만 키운다. 다만 아래 네 가지는 생성 결과를 좌우하므로 반드시 지킨다.

- **타임라인 마커에 카메라를 바인딩해 컷을 전환한다.** 컷 시점이 프레임 단위로 고정되고, 렌더 한 번에 편집된 영상이 나온다.
- **인물마다 몸통 색을 다르게 칠한다.** AI는 회색 캡슐이 누구인지 모른다. 색이 나중에 프롬프트에서 "라임색 = 주인공"처럼 인물을 지목하는 유일한 단서가 된다. 서로 헷갈리지 않는 색을 고르고 매핑표를 기록해 둔다.
- **차량처럼 방향이 있는 물체는 앞뒤를 다르게 표시한다.** 헤드라이트와 테일라이트를 구분해 두지 않으면 앞뒤가 뒤집혀 생성된다.
- **중요한 물체가 카메라에 실제로 크게 보이는지 확인한다.** 프리비즈에서 안 보이거나 작게 뭉개진 부분은 AI가 마음대로 채워 넣는다. 없는 사람이 추가되는 문제의 원인이 대개 이것이다.

구성 후에는 각 컷의 대표 프레임을 뷰포트 캡처나 스틸 렌더로 뽑아 사용자에게 보여주고 구도를 확인받는다. 이 확인은 무료이고, 여기서 놓친 것은 뒤에서 크레딧으로 치르게 된다.

### 3. 프리비즈 렌더 (Bridge)

출력 설정은 다음으로 맞춘다.

| 항목 | 값 |
|---|---|
| 해상도 | 1920 × 1080, 100% |
| 프레임레이트 | 24 fps |
| 포맷 | FFmpeg Video, 컨테이너 MPEG-4, 코덱 H.264, 품질 Medium |
| 렌더 엔진 | EEVEE (프리비즈에 Cycles는 과하다) |
| 샘플링 | Render 12 내외 |
| 모션 블러 | 켬 |

모션 블러를 켜는 이유는 실제 카메라처럼 속도감이 화면에 남아 Seedance가 무브의 빠르기를 더 정확히 읽기 때문이다.

렌더는 백그라운드(별도 프로세스)로 걸어 대화가 끊기지 않게 하고, 끝나면 파일 경로와 길이(프레임 수 ÷ 24)가 샷 리스트와 맞는지 확인한다.

### 4. 프리비즈 업로드와 애셋 시트 생성 (MCP)

프리비즈 mp4를 힉스필드에 업로드해 미디어 ID를 받는다.

이어서 영상에 등장하는 모든 것을 이미지로 먼저 만들어 둔다. 룩은 전적으로 이 이미지들이 결정한다.

- **캐릭터**: 인물당 한 장, 3패널 구성(얼굴 클로즈업 / 머리가 잘린 전신 정면 / 전신 뒷모습). 얼굴을 한 패널에만 두는 이유는, 얼굴이 여러 패널에 반복되면 패널마다 미묘하게 달라져 일관성이 깨지기 때문이다. 등판 그래픽이나 뒷모습이 화면에 나오는 컷이 있으면 뒷모습 패널이 꼭 있어야 한다.
- **차량·방향성 있는 소품**: 정면과 후면을 둘 다. 열리는 부분(트렁크, 문)이 컷에 나오면 열린 상태도 포함한다.
- **장소**: 와이드 한 장과 디테일 한 장.

이미지 모델은 사용자가 지정하지 않으면 MCP의 모델 조회로 현재 권장되는 고품질 이미지 모델을 확인해 쓰고, 2K·3:2를 기본으로 한다. 생성 전 예상 크레딧을 알리고, 결과 시트를 사용자에게 보여 승인받은 뒤 다음 단계로 간다. 룩이 마음에 안 드는 채로 영상을 뽑으면 가장 비싼 단계를 다시 하게 된다.

### 5. 프리비즈 초 단위 분석

**이 단계를 건너뛰면 결과가 어긋난다.** 샷 리스트는 의도이고 렌더된 프리비즈는 실제이므로, 프롬프트는 실제를 기준으로 써야 한다. 프리비즈 영상을 직접 보거나(프레임 추출, 영상 분석 도구) Bridge로 씬의 마커·카메라·키프레임을 읽어, 컷마다 다음을 초 단위로 정리한다.

- 컷 구간(시작·끝 초)과 전환 방식(하드 컷 등)
- 카메라: 화각, 위치(예: 도로 건너편, 후방 3/4), 무브(돌리 인, 팬, 고정)
- 인물별 **화면상 위치**(중앙 왼쪽, 프레임 중앙 등)와 행동
- 방향성 있는 물체가 카메라에 보이는 면(테일라이트가 카메라 쪽 등)

### 6. 프롬프트 작성과 생성 (MCP)

`references/prompt-guide.md`를 읽고 그 구조대로 영어 프롬프트를 쓴다. 다섯 블록(프리비즈 추종 지시와 룩 방어, 색↔인물 매핑, 컷별 초 단위 액션, 포지티브 락, 스타일)이 모두 있어야 하며, 각각이 막는 실패가 다르다.

생성 요청에는 프리비즈를 비디오 레퍼런스로, 애셋 시트 전부를 이미지 레퍼런스로 넣는다. 프롬프트 안의 `@video1`, `@image1…` 번호가 실제로 첨부한 순서와 일치하는지 확인한다. 번호가 어긋나면 엉뚱한 인물이 엉뚱한 자리에 들어간다. 모델은 Seedance 계열 최신 버전, 해상도는 1080p를 기본으로 하되 정확한 모델 ID와 지원 길이는 모델 조회로 확인한다.

영상 생성은 이 워크플로에서 가장 큰 크레딧 지출이다. 제출 전에 예상 비용을 조회해 사용자에게 알리고 진행 의사를 확인한다. 사용자가 이미 예산이나 진행을 명시했다면 다시 묻지 않는다.

### 7. 검수와 부분 재생성

결과를 프리비즈와 컷별로 대조한다(컷 시점, 인물 수, 화면 위치, 차량 방향, 소품 소지자). 어긋난 곳이 있으면 `references/prompt-guide.md`의 문제 해결 표에서 원인을 찾아 **그 원인만** 고친다. 프롬프트 탓이면 해당 컷 설명이나 락을 조이고, 프리비즈 탓이면(안 보임, 컷이 너무 짧음) 블렌더로 돌아가 재렌더한다. 전체를 뭉뚱그려 다시 뽑는 것은 같은 실패를 같은 비용으로 반복하는 일이다.

## 같은 프리비즈로 변주하기

프리비즈 하나는 여러 번 쓸 수 있는 자산이다. 스타일(실사 → 90년대 셀 애니메이션), 캐스트, 차종을 바꾸려면 블렌더는 건드리지 않고 애셋 시트만 새 스타일로 다시 만들고 프롬프트의 스타일 블록과 매핑을 교체한다. 형태가 크게 다른 물체로 바꿀 때(낮은 승용차 → 몬스터트럭)는 치환 지시를 추가한다. 문형은 `references/prompt-guide.md`에 있다.

## 사용자에게 보고할 것

각 단계가 끝날 때 무엇이 확정되었는지 짧게 알린다. 프리비즈 구도 확인(2단계), 애셋 시트 승인(4단계), 영상 생성 전 비용(6단계)은 사용자가 방향을 바꿀 수 있는 지점이므로 결과물과 함께 보여준다. 최종 보고에는 생성된 영상, 사용한 프롬프트 전문, 색↔인물 매핑, 소모 크레딧을 담아 사용자가 다음 변주나 재생성에 그대로 재사용할 수 있게 한다.
